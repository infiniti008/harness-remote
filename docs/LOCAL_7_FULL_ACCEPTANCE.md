## Приёмочные сценарии

Порядок: offline 40k → endurance → MCP → permission/kernel → lifecycle; затем live resume → live Queue/Stop/PID → UI; четырёхчасовой soak последним. Выполняй последовательно; перед и после каждого сценария сохраняй статус, время, exact image ID и ссылку на отдельный приватный лог/artifact directory.

- **Queue/Stop на живом lab:** во время ответа поставить A/B/C в очередь, изменить B, удалить C, сохранить прикреплённый PNG при редактировании B и проверить исходный порядок очереди; затем Send Now. Валидная подача должна дать HTTP `200` ровно один раз; дубликат/конфликт — `409` без повтора; unsupported/slash остаётся в очереди с `409` и видимой ошибкой. Проверить ранний и streaming Stop, гонку Send Now с Stop, поведение около завершения, повторный клик, переключение Session и следующий marker; выполнить 20 live Stop/NEXT циклов, подтвердить новый marker после каждого Stop. После Stop старый queued prompt не должен стартовать; следующий новый marker обязан завершиться в правильной Session. Ошибка подтверждения Stop остаётся ошибкой. Если native-отказ подтверждения в live безопасно не воспроизводится, укажи, что этот путь проверен unit-тестом, а не живым зависанием. Перед live-модельными запросами проверь доступный каталог моделей и квоту; используй короткие маркеры, ограниченное число обращений и модель из последней успешной тестовой сессии.
- **Live resume/recreate:** отдельной тестовой Session и fixture project выполни короткий marker turn, проверь чтение истории и продолжение той же native Session после пересоздания только lab gateway из того же image. Не используй реальные проекты и не меняй пользовательскую native database.
- **Живой PID/thread инцидент:** снимай принадлежавшие lab процессные и thread counts до, во время, сразу после Stop и после ожидания плато; одновременно запиши `pids.current/peak/events`, memory и OOM deltas. Требуется `pids.events max delta = 0`, отсутствие утечки процессов/потоков и возврат к повторяемому idle plateau. Сохрани временные ряды и PID/starttime-идентичности. Укажи вклад самого мониторинга; избегай непрерывного запуска новых docker exec. Не перезапускай gateway между 20 циклами, чтобы не скрыть накопление. Перед любым плановым recreate обязательно сохрани прежние peaks/events. Offline результат не доказывает устранение прежнего PID-128 инцидента на живом lab.
- **Offline native continuation 40k:** `bridge/scripts/native-long-resume-smoke.mjs --items=40000 --gateway-continuation` на точном кандидате в отдельном контейнере `--network=none`, read-only root, private tmp/artifact mount, 1 GiB/0 swap/1 CPU/128 PID; без `--development-small`. Требуются native-generated journal, продолжение через фактический staged gateway, неизменность source prefix/snapshot, bounded paging и resource evidence. Это synthetic-provider проверка, не live-модель.
- **Native endurance:** `bridge/scripts/native-endurance-smoke.mjs --cycles=20 --pause-ms=65000` на точном кандидате и enforced 1 GiB/0 swap/1 CPU/128 PID; без `--development-small`. Сохрани все process/thread samples, Stop/NEXT results, cgroup peaks/events и доказательство plateau. Отличай process RSS от cgroup memory; не называй этот offline прогон live PID-инцидентом.
- **UI:** на production app используй отдельный private CDP endpoint, не `9222`. Запусти `web/scripts/chat-image-preview-smoke.mjs` (6 viewport cases) и `web/scripts/local6-workspace-smoke.mjs` (12 случаев, три раунда). Переменные `HARNESS_UI_CDP_URL`, `HARNESS_UI_APP_URL=http://localhost:15431/` и `HARNESS_UI_ARTIFACTS_DIR` указывай явно; artifacts храни в свежем каталоге lab logs. Проверь реальный synthetic PNG, chat-only границы, rail/header/menu, close/Escape/focus, resize/rotation, смену Session; также cached geometry, поле ввода, размеры вложений, меню, клавиатуру и навигацию. Отдельно проверь 5h/weekly quota с reset и корректное состояние unavailable: synthetic UI smoke сам по себе не доказывает live quota polling. В настоящем браузере зафиксируй реальные visibilitychange и счётчик запросов: в hidden не должно быть новых периодических опросов дольше 60 секунд, при возврате — обновление, без параллельных pollers. Эмулируемые сетевые ответы и настоящие account limits обозначай раздельно.
- **Readonly native MCP:** выполни `bridge/scripts/native-mcp-smoke.mjs` с pinned native/archive в отдельной fixture. Требуй реальный локальный readonly stdio tool marker в native tool output и gateway history; это не проверяет remote HTTP/OAuth MCP.
- **Permission отдельно от kernel:** выполни `bridge/scripts/native-permission-smoke.mjs` и отдельно воспроизведи kernel `bwrap`/user-namespace gate по `docs/LOCAL_4_NATIVE_SAFETY.md`. Зафиксируй раздельно решение native policy и фактическую доступность kernel sandbox. Не включай Full Access, `privileged`, escalation или ослабление sandbox; если ядро отказывает, tools остаются заблокированными, результат kernel gate — `BLOCKED_ENV`. Поле `kernelSandboxAccepted` в permission smoke само по себе не является сертификатом: нужны фактические результаты разрешённой/запрещённой записи и namespace-проб.
- **Lifecycle/OOM:** `bridge/scripts/instance-lifecycle-smoke.mjs --image=<точный локальный image>` должен вернуть пять отдельных `status=passed`, а не только exit 0; отсутствие Docker/image со статусом skipped — не PASS. Он проверяет все пять сценариев, включая намеренный kernel OOM в отдельном fixture. Ожидаемый OOM только в этом fixture не является провалом normal OOM gate. Любой OOM в остальных acceptance runs — FAIL.
- **Четырёхчасовой cache soak:** найди и сначала прочитай прежнюю private lab/scripts реализацию, параметры и отчёт; повторно используй её с этой версией и изолированными данными. Сохрани её проверяемую семантику чтения/кэша; один лишь health polling не заменяет этот soak. Если прежняя реализация отсутствует, явно укажи это и сохрани код фактически использованной проверки для ревью. Четыре завершённых часа, итоговый отчёт и метрики обязательны: незапущенный, незавершённый или всё ещё идущий soak — не PASS.

HTTP/OAuth MCP и multi-machine проверяй только при наличии изолированной учётки, endpoint и fixture; иначе честно ставь `NOT_RUN` с причиной. Не подменяй реальную модель синтетической: отмечай synthetic provider и real model раздельно.
